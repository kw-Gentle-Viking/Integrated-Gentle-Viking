# 한국 주식 AI 자동매매 — 학습·추론 재설계 (Design Spec)

> 작성일: 2026-09-08
> 작업 위치: `/home/user/AI_Gentle_Viking_RE`
> 목표 완료 시점: 2026년 9월 안 (전시회 공식 마감은 11월 중순이지만 실제 목표는 9월)

## 1. 배경 및 문제 정의

캡스톤 졸업작품으로 만든 한국 주식 AI 자동매매 파이프라인(TFT 기반, 삼성전자·SK하이닉스 대상)을 전면 재설계한다. 배경:

- 기존 추론 결과 분석에서 구조적 결함 발견: 관망(hold) 시그널 완전 소실, 시간대별 매수확률 단조증가 편향, 2020~2023 학습 데이터와 2026 현재 간 분포 이동. 임계값 튜닝으로 해결 불가, 재학습 필수라는 결론이 이미 나 있었음(원본 `추론결과_분석_및_개선방향.md`)
- 2026-05-27, 삼성전자·SK하이닉스를 기초자산으로 하는 단일종목 레버리지/인버스(±2배) ETF·ETN 18종(ETF 16 + ETN 2, 상장규모 약 4.3조원)이 상장되면서 두 종목의 변동성이 구조적으로 폭증. 2026년 6월 한 달간 코스피 서킷브레이커가 3회 발동(역대 12회 중 3회가 이 한 달에 집중)했고, 이후 거래정지가 반복적으로 발생(`inference_results.md`에서 실제로 확인됨)

## 2. 스코프

- **담당 범위**: AI 학습·추론·피처엔지니어링 전체. 프론트엔드/백엔드는 다른 팀원 담당이라 이번 재설계에서 제외(추후 연결)
- **백엔드 인터페이스**: 통신 "방법"(폴링/푸시 구조, 인증 방식)만 고정. 통신 주기·페이로드 데이터 구조는 유동적 — 학습 설계 변경에 따라 백엔드도 필요한 만큼 같이 수정
- **역할 분리**: 백테스트 로직은 백엔드가 담당. AI 서버는 예측만 정확히 하면 됨
- **실시간 추론의 위치**: 5분 간격 실시간 추론은 "실시간 자동매매가 동작함을 보여주기 위한 데모용" — 핵심 성능 평가 대상이 아님
- **기존 운영 시스템과의 격리(중요)**: 이 서버에서 원본 캡스톤 코드의 실시간 수집·추론이 crontab으로 실제 운영 중이며, **절대 건드리지 않는다.** 신규 작업은 별도 DB(`stock_db_v2`)와 별도 코드 위치(`/home/user/AI_Gentle_Viking_RE`)에서 완전히 분리해서 진행

## 3. 예측 태스크 재정의

| 항목 | 기존 | 재설계 |
|---|---|---|
| 라벨 대상 | 5분봉 기준 1시간 후 방향 | **일봉 기준 익일 방향** |
| Encoder | 과거 60봉(5분봉, 5시간) | **과거 60거래일 일봉** |
| "오늘" 데이터 | - | 5분봉으로 실시간 계산되는 **미완성 일봉 1개** — 장중 고가/저가/누적거래량/현재가를 그때그때 재계산 |
| 서빙 주기 | 5분마다 | 5분마다 (데모 목적 유지, 위 미완성 일봉이 갱신되며 재추론) |
| 출력 클래스 | 매수/관망/매도 (3진) | 동일 |

**전환 이유**: 5분봉·1시간 호라이즌은 노이즈가 심하고 비현실적. 일봉 호라이즌으로 바꾸되, "실시간으로 동작하는 데모"라는 요구사항은 "오늘"을 실시간 계산되는 미완성 일봉으로 표현해서 충족한다. `time_progress`를 known future 피처로 계속 활용해 "오늘 봉이 몇 % 완성됐는지"를 모델이 인지하게 한다.

**라벨 threshold**: 고정 수치가 아니라, 실제 학습 데이터(1단계 train 구간)에서 매수:관망:매도 ≈ 25:50:25가 되도록 역산해서 결정한다. 정확한 숫자는 데이터 수집 완료 후 계산.

## 4. 모델

- **TFT(Temporal Fusion Transformer) 고정**, 3진 분류(매수/관망/매도) 고정
- 라이브러리: `tft-torch`(PlaytikaOSS)를 `/home/user/AI_Gentle_Viking_RE/tft-torch`에 클론 후 포크 사용
  - 원 라이브러리의 `task_type='classification'`은 `num_outputs=1` 고정 + 분류 손실함수 자체가 없는 사실상 미완성 스텁이었음(원 캡스톤 코드는 `task_type='regression'` + `output_quantiles` 3개로 우회하는 편법을 썼었음)
  - 패치 완료(커밋 `28f735e`, tft-torch 자체 저장소): `config.model.num_classes`를 읽어 `output_layer`가 명시적 N-class 헤드가 되도록 수정, forward 출력 키를 `class_logits`(분류)/`predicted_quantiles`(회귀)로 명확히 분리
  - 회귀 경로 기존 테스트 4개 통과 확인 + 3-class 분류 스모크 테스트로 shape 검증 완료
- **로드맵**:
  - **1안(현재 스코프)**: TFT가 직접 3-class 출력
  - **2안(1안 완료 후 후속 페이즈)**: TFT를 임베딩 추출기로 쓰고 트리 모델(LightGBM/XGBoost/CatBoost 등)이 최종 예측 — PyCaret으로 자동 비교/블렌딩 검토

## 5. 학습 유니버스 & 데이터 기간

### 5.1 유니버스

- 코스닥 제외, **시총 상위 200 고정 스냅샷**
- 스냅샷 기준일: **2019-01-02 종가 기준**(`price_daily × shares_outstanding`으로 계산) — "현재(2026) 기준 시총 상위 200"으로 잡으면 미래에 성공한 종목만 남기는 생존편향(look-ahead bias)이 생기므로, 반드시 **학습기간 시작 시점**의 정보만으로 유니버스를 고정한다
- 실시간 서빙은 여전히 삼성전자·SK하이닉스 2종목뿐(KIS 실시간 API 제약). 모델 자체는 `sector_id`/`market_id` 등 static 피처 기반이라 종목-비의존적 구조이므로 200종목 중 어떤 종목이든 추론 가능

### 5.2 학습 기간 — 2단계 구조

레버리지 관련 피처는 2026-05-27 이전엔 항상 0이므로, 이 구간을 통째로 test로 빼면 모델이 레버리지 국면을 한 번도 학습하지 못하는 문제가 생긴다. 이를 해결하기 위해 학습을 2단계로 나눈다.

**1단계 — 모델 선택/벤치마크/피처 ablation용**
- train: 2019-01-02 ~ 2023-12-31
- val: 2024-01-01 ~ 2024-12-31
- test: 2025-01-01 ~ 2025-12-31
- **2026(레버리지 국면, 역대급 변동성 이상치 해) 전체를 배제** — 이상치 해의 노이즈 없이 아키텍처/피처 조합을 깨끗하게 비교하기 위함. 레버리지 플래그는 이 단계에서 항상 0(무해하지만 학습에 기여 없음)
- 기존 캡스톤 모델의 val/test 연도(2024/2025)와 겹쳐서, 재설계 전후 성능 비교도 가능

**2단계 — 실배포용 최종 모델**
- 1단계에서 선택된 아키텍처/피처 조합을 **2019-01-02 ~ 현재(2026, 레버리지 국면 포함) 전체로 재학습**
- 이 단계에서는 레버리지 플래그가 실제로 0/1을 오가며 의미 있게 학습됨
- 이 모델이 실제 서빙되는 최종 모델

**설계 원칙(근거)**: "레버리지 국면에서 성능이 안 나오는 건 변명 가능(역대급 이상치 해라서), 레버리지가 아닌 국면에서 성능이 안 나오면 변명이 어렵다." 따라서 모델 자체의 실력 판단(1단계)은 반드시 변명이 안 되는 안정적 구간으로 하고, 실전 배포용 모델(2단계)만 레버리지 국면까지 반영한다.

### 5.3 데이터량 근거

TFT 원 논문(Electricity 벤치마크)은 약 50만 샘플(8개월치) 사용, 최소 약 2만 샘플부터 동작하되 데이터가 많을수록 유리. 시총 상위 200 × 약 2000거래일(2019~2026) ≈ 40만 행, encoder 60일 슬라이딩 윈도우 적용 시 약 38만 개 샘플로 벤치마크 규모에 근접. 반면 삼성전자·SK하이닉스 2종목만으로는 동일 기간 약 4천 개 샘플에 불과해 TFT 학습에 부족하다고 판단해 200종목 풀링을 채택.

### 6.3 계산 피처

리밸런싱 금액 = 펀드 순자산(전일 기준) × (기초자산 수익률 − 펀드 자체 수익률) — ETF 업계에 문서화된 표준 공식(참고: ETF Database, Leverage Shares).

| 피처 | 계산 |
|---|---|
| `lev_total_volume` | 종목 관련 레버리지+인버스 ETF/ETN 전체의 당일 거래대금 합 |
| `lev_total_aum` | 전체 순자산총액 합(주가×상장좌수로 근사) |
| `lev_aum_to_mktcap` | 레버리지 상품 총 AUM ÷ 기초종목 시가총액 |
| `est_rebalancing_flow` | `lev_total_aum(전일) × 기초자산 당일 수익률 × (배율−1)` (상품별 합산 근사) |
| `is_vi_triggered` | 당일 VI 발동 여부 |
| `vi_count_recent5d` | 최근 5거래일 VI 발동 횟수 |

**타이밍**: `est_rebalancing_flow`는 당일 종가가 확정돼야 계산 가능하므로 "오늘자 피처 → 내일 라벨" 구조로만 사용한다(오늘 이미 끝난 사건을 내일 예측에 쓰는 것이므로 데이터 누수 아님).

**레짐 처리**: 학습 기간을 레버리지 출시 이후로 제한하지 않고 2019년부터 길게 사용하며, 위 피처들은 출시 전엔 자연스럽게 0/부재로 채운다.

## 7. 피처 엔지니어링 방법론

- 고정된 최종 피처 리스트를 미리 정하지 않는다. 기존 피처(가격/거래량 기술적, 수급, 밸류에이션, 매크로, 섹터, 이벤트 등, 총 55개 기반)를 기간만 확장해서 최대한 유지하고, 위 레버리지 피처를 추가한 뒤, **넉넉하게 다 만들어두고 add/remove ablation 실험으로 최종 학습 피처 조합을 확정**한다
- 실험 트래킹: **wandb**, 데이터/피처셋 버전관리: **dvc**

## 8. 결측치/이상치 처리

- **결측치**: 재무데이터(PER/PBR 등, 2026-09-08 기준 스코프에서 제외됨) 결측은 기존 원칙대로 0으로 채우되 "적자기업"이라는 의미 있는 정보로 취급. 이 원칙은 5분봉/일봉 전환과 무관하게 유효
- **결측치(2026-09-08 추가, 우선 원칙)**: 값이 일시적으로 비어도 그 종목/시계열 자체는 계속 존재하는 경우(매크로 지표 휴장일, 특정일 데이터 누락 등) — **행을 버리지 말고 직전 값으로 채운다(forward-fill)**. "0으로 채우기"는 결측 자체가 의미 있는 정보인 경우(적자기업의 PER/PBR)에만 쓰고, 그 외에는 ffill을 기본값으로 한다. 실제로 Task 6(매크로 백필)에서 이 방식으로 2019-01-01(전체 기간 첫날, ffill할 과거값 자체가 없는 경계 케이스 1건 제외) 이후 결측 0건 달성 확인됨. "종목이 그 시점에 아예 존재하지 않음"(상장 전, 상장폐지 후)은 ffill 대상이 아니라 정당한 제외 사유
- **클리핑/스케일링**: 기존 하드코딩된 고정값(예: `log_ret ±0.2`, 5분봉 기준으로 튜닝됨)은 그대로 재사용하지 않는다. 대신 **1단계 train split(2019~2023)에서 분위수(0.5~99.5%) 또는 ±5σ를 직접 계산**해서 클리핑 기준으로 사용 — 일봉 특성과 레버리지 국면의 두꺼운 꼬리 분포에 자동으로 맞춰짐
- 기존 원칙(train에서 fit → val/test엔 그대로 적용, 데이터 누수 방지)은 그대로 유지

## 9. 데이터 파이프라인 & DB 설계
