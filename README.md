# Integrated Gentle Viking

한국 주식(코스피 상위 200종목) 대상으로 **TFT(Temporal Fusion Transformer) 기반 AI 추론 결과를 받아 모의투자 계좌에서 자동매매를 실행하는 시스템**입니다. 웹 프론트엔드에서 종목을 고르고 자동매매를 켜면, 백엔드가 AI 신호와 전략을 조합해 주문을 내고, 체결 기록과 수익률을 확인할 수 있도록 만든 캡스톤 프로젝트입니다.

## 프로젝트 목표

- AI 모델이 다음 거래일 주가 방향(매수/관망/매도)을 예측하고, 그 신호가 실제 주문과 수익률로 이어지는지 검증합니다.
- 장중 실시간 추론과 실제 체결 경로가 끝까지 동작하는지 확인하고, 한 달 단위 수익률을 측정합니다.
- 서비스 형태(로그인, 리포트, 배포)는 핵심 검증이 끝난 뒤 단계적으로 붙입니다.

## 전체 구조

```
[데이터 수집]  운영 DB(stock_db, 350종목): 1분봉·5분봉·일봉·수급·매크로·공시
      │
      ├─ 일별 복사·피처 빌드 ──▶ [AI DB (stock_db_v2, 200종목)] feature_pool 등
      │                                 │
      │                                 ▼
      │                    [AI 추론 서버 (serving, 8001)]
      │                     · 5분 추론 (지정 종목)
      │                     · 명령 중계 (백엔드 큐 → /command)
      │                                 │  POST /ai/realtime, /ai/callback
      │                                 ▼
      │                    [백엔드 (FastAPI, 8000)]
      │                     · 예측 저장, 이력 기록
      │                     · 자동매매 루프 (전략 + AI 신호 → 배분 → 리스크 → 주문)
      │                     · 체결·판단 기록
      │                                 │  REST (Bearer 토큰)
      │                                 ▼
      │                    [프론트엔드 (Next.js, 3000)]
      │                     · 종목 탐색, 자동매매 바구니, 포트폴리오, AI 판단 보기
      │
      └─────────────▶ [한국투자증권 모의투자 API] 시세 · 잔고 · 주문 · 체결 조회
```

## 핵심 흐름

### 1. 데이터와 피처
- 운영 수집기가 1분봉과 5분봉, 일봉, 수급, 밸류에이션, 매크로 지표를 매일 쌓습니다.
- AI DB(`stock_db_v2`)는 AI 학습 유니버스 200종목만 가지며, 매일 16:45에 운영 DB에서 공통 테이블을 복사하고 피처(`feature_pool`)를 다시 만듭니다.
- 장중 추론에는 같은 날 5분봉으로 만든 "미완성 일봉"을 마지막 행으로 붙입니다.

### 2. AI 추론
- 모델은 **일봉으로 학습한 TFT**이며, 라벨은 "다음 거래일 수익률의 종목 간 상대 순위"(상위 30% 매수, 하위 30% 매도, 나머지 관망)입니다.
- 확정 모델은 `v3_structure_nowd_cs` (seed 0)이고, 세 시드에서 재현성을 확인했습니다.
- 추론 결과는 `매수/관망/매도` 확률과 `점수 = p_매수 − p_매도`로 나오고, 모든 결과에 모델 버전이 붙습니다.
- 장중 추론은 학습 조건(확정된 일봉)과 입력이 다르므로 참고용으로 보고, 한 달 검증은 장 마감 후 확정값 기준으로 맞추는 것을 원칙으로 합니다.

### 3. AI → 백엔드
- 추론 서버는 5분마다 `POST /ai/realtime`으로 결과를 보냅니다. 백엔드는 종목별 최신 예측을 저장하고 이력(`ai_prediction_history`)에 남깁니다.
- 사용자가 요청한 1회 분석(ONCE)은 백엔드 큐에 쌓이고, 중계 프로세스(`poll_commands`)가 매분 가져가 AI 서버에 전달합니다. 결과는 `/ai/callback`으로 돌아옵니다.

### 4. 자동매매 한 사이클
1. 사용자가 바구니에 종목을 담고 자동매매를 시작하면, 백엔드는 AI 서버에 종목 등록을 요청하고 사용자별 루프를 띄웁니다.
2. AI 예측이 들어올 때마다 루프가 한 번 돕니다.
3. 실제 잔고로 보유 수량을 읽고(실패하면 이번 사이클 건너뜀), 종목별 예측을 모읍니다. 30분 넘은 예측이나 없는 예측은 HOLD로 봅니다.
4. BUY 신호 중 확신도 기준을 넘는 종목에 투자 가능 금액을 배분합니다.
5. 종목마다 전략(ultra_safe 등)이 주문을 만들고, AI 신호와 전략 신호가 맞아야 실행합니다.
6. 리스크 한도(종목당, 1회 주문, 전체 노출)를 통과하면 KIS에 시장가 주문을 냅니다. 일시 장애만 재시도하고, 영업일 아님 같은 영구 오류는 바로 멈춥니다.
7. 체결 여부와 판단은 `trade_logs`와 `auto_trade_decisions`에 남습니다.

### 5. 사용자 화면
- 종목 목록과 순위에서는 모든 종목을 볼 수 있지만, **자동매매 바구니에는 AI 학습 종목 200개만** 담을 수 있습니다.
- 바구니는 최대 5종목입니다.
- 포트폴리오 화면에서 최신 AI 판단(오래된 신호는 표시), 최근 주문과 실패 여부, 자동매매 상태를 봅니다.

## 실행과 점검

### 로컬 실행 순서
1. 데이터: 운영 수집 크론, AI DB 일별 갱신 크론 (`scripts/daily_v2_refresh.sh`)
2. AI 추론 서버: `uvicorn serving.api_server:app --port 8001`
3. 백엔드: `uvicorn app.main:app --port 8000` (환경변수는 `.env`, 커밋되지 않음)
4. 프론트엔드: `npm run dev` (port 3000)
5. 크론: 5분 추론(`serving.inference_pipeline`), 명령 중계(`serving.poll_commands --once`), 서버 헬스체크

### 점검
- `scripts/preflight_check.sh` (AI 레포): 프로세스, 크론, 종목 목록 일치, 데이터 최신 여부, KIS 잔고 조회를 읽기 전용으로 점검합니다.
- 스모크 주문: `POST /trade/smoke-order` (모의계좌, 비운영 환경, AI 종목만, 1주). 체결 경로를 장 시작 직후 확인할 때 씁니다.

## 알려진 제약

- 1~2개 신호만 나오면 `redistribute`와 `cap_cash`에서 결과가 달라집니다. 정책 선택 전까지는 주의가 필요합니다.
- 5분봉 워밍업은 운영 DB 이력을 씁니다. 백엔드가 운영 DB에 접근할 수 있어야 합니다.
- 장중 추론은 학습 조건과 다른 입력이라 참고 지표로 봅니다.
- Gemini 무료 티어에서 간헐적인 과부하(503)가 나면 리포트 생성이 실패 문구로 대체됩니다.
- 시세 조회 토큰은 1분에 1회 제한이 있어서, 재시작 직후 바로 여러 번 호출하면 실패할 수 있습니다.
